# v0.6.6（プレリリース）

関連ノートの検索範囲をVaultのフォルダ構成に合わせて限定できるようにし、
あわせてサイドバービューの二重表示とキャッシュ書き込みの不具合を修正した検証版。

## 検索範囲

- 「同じルートフォルダのみに限定」設定を追加。デフォルトはOFFで、従来どおり
  Vault全体から候補を探す。
- ONの場合、アクティブノートと同じ最上位フォルダ以下のノートだけを、関連ノートと
  タグ提案元の対象にする。
- `Projects/Alpha.md` と `Projects/Archive/Beta.md` は同じルートとして扱い、
  `Projects/Alpha.md` と `Areas/Beta.md` は別ルートとして扱う。
- Vault直下のノートは、他のVault直下ノートとのみ照合する。
- 検索時のフィルターとして適用するため、設定変更によるインデックス再構築は不要。

## 対応バージョン

- `minAppVersion` を1.4.0から1.12.7へ引き上げた。
- 引き上げの理由は、新しいAPIを使い始めたからではない。1.4.0という値は実機で
  確認したものではなく、動作を検証していないバージョンをサポート対象として
  宣言しないための変更である。今後も、実際に検証したバージョンを下限とする。
- 1.12.7より前のObsidianには、`versions.json` を通じて引き続き0.6.5が配信される。

## 修正と整理

- サイドバービューが二重に開く原因を修正。`activateView()` はleafの有無を
  同期的に調べたあと `setViewState()` を待つ一方、呼び出し元（起動処理と
  コマンド）はどちらも完了を待っていなかった。起動直後にコマンドを実行すると
  両方が「leafは無い」と判断し、`getRightLeaf(false)` が呼び出しごとに別のleafを
  返すため、同じサイドバーに同じビューが2つ生成されていた。進行中の処理を
  共有して、確認と生成をひとまとまりにした。
- 余分なビューの整理を、同じコンテナ内の重複だけに限定。`getLeavesOfType()` は
  メイン領域、左サイドバー、右サイドバーの順に走査するため、先頭以外をすべて
  閉じる従来の処理では、ビューをメイン領域のタブにも置いているユーザーの
  サイドバー側が消えていた。左右サイドバーの併用やポップアウトへの常駐は
  維持される。
- 形態素キャッシュの定期フラッシュが、書き込み対象のない時点で走ると
  未書き込みフラグを落としていた。data.jsonからキャッシュファイルへの移行が
  再起動まで持ち越される場合があったのを修正。
- 設定タブの見出しを、独自の `<h3>` からObsidianの `Setting.setHeading()` へ
  変更。コミュニティプラグインのガイドラインに合わせ、テーマ側の見出し
  スタイルにも追随する。
- `DataAdapter` に渡すキャッシュファイルのパスを `normalizePath()` に通す。
- 自前の `DebouncedAction` を廃止し、Obsidianの `debounce()` に統一。
  `Debouncer.run()` が1.4.4以降で使えるため、独自実装の理由がなくなった。
- `getAbstractFileByPath()` + `instanceof TFile` を、1.5.7以降の
  `getFileByPath()` に置き換え。
- 起動時のキャッシュ復元で、本文側の復元に失敗した場合に、消費済みの
  タイトル配列が再利用され得た経路を塞いだ。現行の検証順では到達しない。

## ドキュメント

- 英語・日本語README、現行アーキテクチャ、モバイル検証手順を更新。
- モバイル検証手順のバンドルサイズを実測値（26.25 MB）に修正。

## 検証状況

- 自動テスト、型検査、製品ビルド、リリース資産と第三者ライセンスの検証を実施。
- 同一ルート、別ルート、Vault直下、デフォルトOFFを自動テストで確認。
- サイドバービューの修正は、起動中のObsidianで確認済み。同時呼び出しで生成される
  leafが1つになること、メイン領域とサイドバーの併用が両方残ること、同一サイドバー
  内の重複だけが解消されることを実機で確認した。
- v0.6.1までの基本動作はiPhone 13で確認済み。
- v0.6.6の同一ルート設定、長押しコピー、起動キャッシュのモバイル実機確認と、
  Androidでの確認は未実施のため、引き続きプレリリース扱いとする。
