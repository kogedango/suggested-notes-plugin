# v0.6.7（プレリリース）

起動のたびにサイドバービューが自動で開かないようにした検証版。

## 起動時のビュー

- Obsidianの起動時に、このビューを前面に出す処理をやめた。ビューを開くのは、
  コマンド「開いているノートの関連ノートを表示」を実行したときだけになる。
- モバイルでは右サイドバーが画面を覆うドロワーであるため、従来は起動のたびに
  このビューが開いた状態からアプリが始まっていた。デスクトップでも、起動時に
  右サイドバーのアクティブなタブをこのビューが奪っていた。
- 起動時にビューのleafを作る動作自体は残す。作成した直後の
  `setViewState()` は `active: false` で呼ぶ。`active: true` だけでも
  モバイルのドロワーが開く可能性があるため、条件分岐で避けるのではなく、
  起動経路からアクティブ化そのものを外した。
- leafがすでにある場合は何もしない。ユーザーが配置したビューの位置や、
  左右サイドバー併用のレイアウトは従来どおり維持される。
- `revealLeaf()` の呼び出しを、二重leafを防ぐための共有プロミスの外に移した。
  起動時の呼び出しは「開かない」指定で進むため、その進行中にコマンドが
  実行された場合、共有プロミスをそのまま返す構造ではコマンドが無反応に
  なっていた。leafの生成だけを排他し、表示は呼び出しごとに判断する。
- Obsidian 1.7以降、一度もアクティブになっていないサイドバーのビューは
  遅延生成される。ビューを集める処理は `instanceof` で絞っているため
  遅延中のleafは対象から外れ、ユーザーがタブを開いた時点で `onOpen()` の
  更新要求が走る。

## 検証状況

- 自動テスト、型検査、製品ビルド、リリース資産の検証を実施。
- 起動時にビューが開かないこと、コマンドからは開くことのモバイル実機確認は
  未実施。この確認がこのプレリリースの目的である。
- v0.6.6時点で未実施のモバイル確認（同一ルート設定、長押しコピー、起動
  キャッシュ、Android）も引き続き未実施のため、プレリリース扱いを継続する。
- `main.js` は26.25 MB（27,522,047バイト）で、0.6.6から実質的に変わらない。
