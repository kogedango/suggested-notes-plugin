# 語彙データを持つかどうかの決定（2026-07-22）

## 決定

**このプラグインは語彙データを所有しない。1a・1b とも却下する。**
**代わりにタイトル経路の TinySegmenter を有効化する。**

- **1a 却下**：`synonyms.txt` 由来の表記等価テーブル。実 vault の測定で、
  既定経路の新規接続が **0 件**、opt-in 経路が **12 件**（1366ノート）。
  所有・ライセンス・出自監査・カバレッジ方針・保守のコストに見合わない。
- **1b 却下**：lex CSV 本体（lemma・品詞・活用型）。1a より広い範囲とコストを持ちながら、
  測定で確認できた対象は `育てる/育てた/育てて` のみ（`tokenizeContrast.dataset.ts:55`）。
- **M1 採用**：タイトル経路の `segment` を true にする。データ追加ゼロ、
  ライセンスゼロ、所有コストゼロ。0トークンのタイトルが 37 → 7 に減り、
  `CLAUDE.md:54` が「既知のギャップ」と呼ぶ全ひらがなタイトルも閉じる。

これは「語彙データは制約違反だから」ではない。制約には反しない（オフライン・決定的・
バンドル可能）。**測って、割に合わないと判断した**という記録である。

### 判断を覆す条件

以下のいずれかが示されれば再検討する。

1. 単一著者でない vault（他人の記事のクリップが多い、複数人の文書を集約している）で
   表記ゆれの共起率が有意に高いこと。この vault では 44,820 グループ中 103（0.23%）だった。
2. 候補集合が飽和していない vault（タグ・リンクが疎）で、表記等価が
   順位付けではなく候補生成に効くこと。この vault では 97.6% が既に候補だった。
3. `育てる/育てた` 型の活用正規化に、`tokenizeContrast` の fixture を超える
   独立した製品証拠が出ること。

## 根拠

### 1. 規則では原理的に届かない領域があることが測定で確定した

contrast harness の全ペアを両モードでトークナイズし、失敗を4分類した測定：

| | identified | emptyBoth | emptyOne | disjoint | false merge |
|---|---|---|---|---|---|
| segment=false（既定タイトル経路） | 4 | 4 | 12 | **0** | 0/5 |
| segment=true（opt-in 本文経路） | 5 | 0 | 1 | **14** | 0/5 |

本文経路の失敗はほぼ全て `disjoint` である。両側ともトークンを出していて一致しない。
これは正規化の問題であり、語彙的同一性の知識なしには解けない。

`NEGATIVE_CONTRAST_PAIRS`（`src/util/tokenizeContrast.dataset.ts:82`）は、
規則による広い推論が安全でないことを示すために作られている。
`立ち方/立方`、`見せ方/見方`、`生き物/生物` は全て2漢字骨格が一致するため、
漢字骨格キーのような規則は 5/5 の誤マージを生む。

### 2. ハード制約に反しない

禁止されているのは AI・埋め込み・ネットワーク・常駐プロセス（CLAUDE.md:5）。
辞書は禁止項目ではない。バンドルされた静的表はオフラインで決定的であり、
`tiny-segmenter` が sanction された理由（サイズ・オフライン・決定性）を全て満たす。

CLAUDE.md:11 の "dictionary-free" という記述は失効するが、
これは `tiny-segmenter` の性質の描写であって製品制約として列挙されたものではない。

### 3. すでに語彙的判断の当事者である

`KANJI_STOPWORDS` / `JA_MIXED_STOPWORDS` / `JA_STOPWORDS` は、
どの日本語形が話題性を持つかを決定している（`src/util/tokenize.ts:14,170,214`）。
fixture は `子ども = 子供` と `生き物 ≠ 生物` を明示的に宣言している
（`tokenizeContrast.dataset.ts:65,82`）。

辞書を拒否しても中立にはならない。判断がヒューリスティックと欠落の中に暗黙化するだけである。
語彙表は、その判断を**レビュー可能な形に外出しする機構**として位置づける。

## 価値評価（2026-07-22、Claude が自説を攻撃し Codex と検討）

「語彙表だけがこの失敗を解ける機構である」ことと「解く価値がある」ことは別の主張である。
前者から後者へ滑っていたため、4つの反論を立てて検証した。

**残った反論：タイトルの存在欠陥にはバンドル済みの安い代替がある。**
測定した中で最大の効果は異表記統合ではなく、`segment=false` で25表層形中13形が
0トークンになること（同一表記どうしすら一致しない）。しかしこれは TinySegmenter で直る：

    ひっこし        seg=false []        seg=true ["ひっこし"]
    引っ越しの記録   seg=false ["記録"]   seg=true ["記録","引っ越し"]
    打ち合わせメモ   seg=false ["メモ"]   seg=true ["メモ","打ち合わせ"]

CLAUDE.md:54 が「既知のギャップ」と呼ぶ全ひらがなタイトルも同時に閉じる
（`tokenize.ts:220` の長さ3以上の平仮名分岐）。バンドル済み・sanction 済み・決定的で、
新規のデータ所有・ライセンス・カバレッジ責任がゼロ。**存在の回復は語彙表の仕事ではない。**

ただしコストは零ではない。TinySegmenter は散文向けの調整で、タイトルは短い名詞句である
（`titleTokens.ts:90`）。誤分割や汎用語がノイズ候補を生みうる。
`TITLE_TOKEN_EXPANSION_MAX_DF_RATIO`（20%）は高頻度語の扇形展開を抑えるが、
稀なノイズは抑えない（`scoring/index.ts:31,141`）。

**崩れた反論1：「効果は既定OFFの経路に落ちる」。**
タイトルトークンは**候補集合そのものを広げる**（`scoring/index.ts:141-146`、
コメントに "Metadata-only, on by default — no enabled flag to gate this behind"）。
表記等価キーが候補を入れる唯一の機構である場合、`titleWeight` が3であることは無関係である。
得点の話ではなく、候補として存在するかどうかの話になる。

**崩れた反論2：「6信号の加重和なので1トークンの取りこぼしは軽い」。**
本文経路には閾値がある。`rankSalient` は `if (n < 2) continue; // singletons can't
produce shared signal`（`bodyTokens.ts:271`）。
異なる表記を使う2ノートは、それぞれ df=1 の単独トークンを作り、**本文signalがゼロになる**。
共有グループキーは df=2 を成立させ、使えなかった証拠を適格な証拠に変える。
これは加算ではなく閾値効果であり、しかも「タグもリンクも共有しない」という
本文照合が存在する理由そのものの領域で起きる（CLAUDE.md:59）。

**未決の反論：表記ゆれは著者間の現象ではないか。**
表記の癖は個人的な習慣であり、単一著者のvaultには両表記がそもそも現れない可能性がある。
ただしリポジトリにはこれを裏づける記述がない。ドキュメント化されている所有者固有の事実は
「古いノートを改訂しうる」だけである（CLAUDE.md:44）。習慣の経年変化・クリップした他人の文章・
引用も同程度にありうる。**この反論は調査の優先順位を決めうるが、語彙正規化の却下は支えない。**
vault 統計は作業の順序を決めても正当化はしない、という所有者の方針にも整合する。

### 実 vault での測定（2026-07-22、Main vault 1366ノート）

**この測定は 1a の採用を支持しない。** 数値は下記。単一vaultの結果なので
採否を確定させるものではないが、少なくともこの vault に導入する根拠は出なかった。

前提として、**候補集合が既にほぼ飽和している**。タグ／リンク共有で
909,821 / 932,295 ペア（97.6%）が既に候補である。タグとアウトリンクの候補展開には
df 上限が無い（`scoring/index.ts:102-110`）ため、これは製品の実挙動として正しい。
したがって新しいトークン一致の大半は、候補の追加ではなく順位付けにしか効かない。

**M1 タイトルのセグメンタ ON**（語彙表なし）

    0トークンのタイトル: 37 -> 7
    異なりタイトルトークン: 1575 -> 1848
    展開適格なタイトルトークンを共有するペア: 10531 -> 10607（新規 76）
      うちタグ/リンクで未接続: 4

**M2 両表記が実際に共起するグループ**（`表記ゆれ` のみ、アルファベット・略語を除外）

    44,820 グループ中 103（0.23%）のみが、2つ以上の異なる表記を vault 内に持つ

「表記ゆれは著者間の現象であり、単一著者vaultには両表記が現れにくい」という
反論は、この vault では**データに支持された**。

**M4 1a の追加効果**（セグメンタON の上に載せた差分、strict tier）

    タイトル: 新規 15 ペア、うち未接続 0
    本文A（キーをランキング前に追加）: 新規 109 / 既存 34,741 を破壊
    本文B（キーをランキング後に追加）: 新規 243（未接続 10）/ 破壊 0
    本文C（df判定のみグループ単位、キーは後付け）: 新規 217（未接続 12）/ 破壊 277

**統合点に関する設計上の発見。** 本決定文書が当初書いていた「加算的にキーを足す」は、
top-N（既定40）という有限予算の中でキーが既存トークンと競合するため、
**既存ペアを 34,741 件破壊する**。得たものの300倍を失う。
実装するなら B か C（ランキング後にキーを付す）でなければならない。
ただし B は df=1 の単独表記が salient に到達しないため、
「閾値効果」——1a を支持する最強の論拠だったもの——を失う。
C はそれを回復するが、この vault では追加効果が 12 ペアに留まった。

**判定：1a を却下する。**

Codex が事前に置いた反証条件は「タイトル候補ペアの新規がゼロ、かつ
df境界と両ノートの top-N を生き延びる本文ペアの新規がゼロ」だった。
タイトル側はゼロ。本文側は 12 で、文字どおりのゼロではない。
だが 1366 ノート・932,295 ペアに対する 12 件は、閾値の趣旨——
「実 vault で運用上の利益があるか」——を満たさない。
条件の字面に助けられて採用する理由はない。

却下は単一 vault の計数だけに拠るものではない。三つの根拠のうち二つは
vault 固有ではない。

1. **top-N の押し出し（vault 非依存）**：加算的なキーは有限予算内で既存トークンと
   競合する。この構造は任意の vault で成立する。回避策（B/C案）は存在するが、
   B は 1a の最強の論拠だった閾値効果を失い、C は複雑さに対して 12 件しか返さなかった。
2. **候補集合の飽和（製品の性質）**：タグ・アウトリンクの候補展開に df 上限が無い以上、
   よく張られた vault では候補集合が飽和し、語彙一致は順位付けにしか効かない。
   飽和の程度は vault 依存だが、飽和しうるという構造は製品の性質である。
3. **表記の共起率 0.23%（vault 固有）**：これだけが単一 vault の計数であり、
   単独では却下を支えない。ただし機構——表記の癖は個人の習慣であり、
   単一著者の vault では両表記が揃いにくい——は、このプラグインの
   想定利用者層に一般化する。

### 分類の訂正

- **分類2（ゲート漏れ）を「無害」とした整理は誤り。** `2 ≤ df ≤ 40%` に収まる漏れ形は
  ゲートを通過して IDF 重みを得る（`bodyTokens.ts:271`）。`stopwords.ts:10` が主張しているのは
  「高頻度ノイズは復元可能な形で抑制される」であって、あらゆる漏れ活用形が無害だ、ではない。
- **分類3（辞書でも解決不能）は誇張。** `synonyms.txt` に無いことは**出典のカバレッジ欠落**であって
  語彙的に到達不能という意味ではない。全ひらがな文字列も TinySegmenter 経由で部分的に到達可能。
  真に未解決のまま残るのは表層形から決まらない曖昧性（`行った` = `行く`/`行う`）で、
  これは統合しないままにする。

## 資産の形

### 単一資産

表層形のテーブル。各レコードは語彙情報と、任意の正規化グループIDを持つ。

- 一つの表層形が**複数のレコードを持つことを許す**。同音異義語に単一のグループIDを割り当てられるとは限らない。
- 関連する語義すべてにわたって安全な等価だけがグループIDを得る。

### 統合点：加算的なトライ走査

生の文字列に対する最長一致走査。後段の正規化ではない。

- これは軽量な辞書ベース分かち書きである。「認識にすぎない」という理解は誤り。
  未マッチ領域を無視するとしても、決定的な重なり・境界規則の仕様が要る。
- 既存の正規表現経路・TinySegmenter 経路と**並行して**走る（`src/util/tokenize.ts:53,80`）。
  それぞれ異なるトークン種別を覆っており、語彙表はそれらを抑制しない。
- 完全な分かち書きは狙わない。未知領域は現行挙動のまま。
- 実行順は NFKC・markup 除去の**後**、最終的なストップワード濾過の**前**（`tokenize.ts:80` の現行順序に合わせる）。

### 不変条件

- **現在 eligible なトークンは決して除去しない。** グループIDは照合キーを追加するだけで、置換や書き換えをしない。
- ただし「加算的だから誤マージ0」は論理的に保証されない。
  誤った等価グループや、未知の長い複合語の内部で認識された部分語は誤マージを生みうる。
  正しい不変条件はより狭い：**NEGATIVE_CONTRAST_PAIRS のどのペアも共有語彙キーを獲得しない**。
- **ストップワードが常に勝つ。** 既存のストップワード集合は実在の語を意図的に抑制している
  （`考える` `行く` `関する` — `src/data/stopwords.ts:191,227`）。語彙表がこれを復活させてはならない。

### frozen corpus との関係

バンドルされた不変の語彙表は、corpus 由来の `standalone` より**安全**であり、
過去の `df` 破損の失敗クラスを再現しない。

- 失敗した設計は corpus 統計の**逐次変異**だった。`df` は破損しえて、
  無制限のトークン保持を要求したため、いまは全体置換でしか変わらない（CLAUDE.md:85）。
- `standalone` が凍結されているのも同じ理由で、一つのノートの編集が
  他の全ノートの信頼判定を変えうるからである（CLAUDE.md:76）。
- バンドル語彙表にはこの依存がない。vault の編集は語彙表を変異させられず、
  あるノートの認識が別のノートの認識を変えることもない。

**唯一の必須不変条件**：corpus と query は同一の語彙表バージョンを使う。
セグメンタフラグの不変条件（CLAUDE.md:83）と同じ性質である。
語彙表の差し替えはプラグインのバージョン更新と同時にのみ行い、直後に全体リビルドを走らせる。
本文索引・タイトル索引はどちらも既に全体リビルドを持つので、既存機構に収まる。ホットスワップはしない。

## 出典とライセンス

`SudachiDict/LEGAL` を実物で確認した結果：

- 全ファイルは **Apache-2.0**
- `small_lex.csv` は **UniDic の一部**を含む（UniDic Consortium, New BSD）→ 告知保持義務
- `core_lex.csv` / `notcore_lex.csv` は **NEologd の一部**を含み、
  NEologd は**はてなキーワード一覧**の表記・読み仮名の大半を使用、著作権は株式会社はてな

したがって：

- **small から始める。** UniDic(BSD) 由来で完結し、出自が追える。
- **core / full は出自監査まで取り込まない。** NEologd 経由のはてなキーワード由来を評価する必要がある。
- share-alike は回避できるが、**帰属表示・告知保持・出自レビュー・変更点の記載は回避できない。**
- UniDic 自体は GPL/LGPL/New BSD の三重ライセンスなので、BSD 選択は正当。
- **JMdict は採らない。** CC BY-SA に加えて更新手順の義務がある。
- **IPAdic を「BSD系」として当てにしない。** 原 IPAdic の条項には歴史的な争点がある。
  BSD 系の後継として通常挙げられるのは NAIST-JDIC であり、別の資産である。

## 第一歩（最小の出荷単位）

**データ形式 ＋ 生タイトルへのトライ走査を、fixture で既に承認済みの等価グループだけで実装する。**
辞書の取り込みはまだ行わない。

初期エントリ（`tokenizeContrast.dataset.ts:23` の positive groups）:

    引っ越し / 引越し / 引越
    打ち合わせ / 打合せ / 打合
    申し込み / 申込み / 申込
    問い合わせ / 問合せ
    振り返り / 振返り
    取り組み / 取組み / 取組
    気づき / 気付き
    子ども / 子供

**活用形は初期スコープから除外する。** 理由は2つあり、混同しないこと。
`考える/考えた` の失敗はストップワードの非対称であって語彙表の欠落ではない
（`tokenizeContrast.dataset.ts:55`）。一方 `育てる/育てた` は真の positive で、
語幹の知識がないために失敗している。後者は語彙表で解けるが、
表層形の等価グループではなく lemma と活用型を要するため、第一歩の資産形状に収まらない。

なぜこれが既定経路に効くか：タイトルは `tokenize(..., false, ...)` を呼び（`titleTokens.ts:90`）、
正規表現は長さ2以上の漢字ランしか認識しない（`tokenize.ts:12`）。
`引っ越し` は 引〔っ〕越〔し〕 で長さ1のランが2つになるため、現在**1トークンも出ない**。
トライ走査は TinySegmenter を有効化せずにこれを回復する。

ただし範囲を誇張しないこと。**この第一歩が直すのは収録済みの語だけである。**

そして価値評価の結果、**「内部に平仮名を含むタイトルが何も出さない」という一般の欠陥は
語彙表の担当から外れた**。それは TinySegmenter で直す（上記「価値評価」）。
語彙表がタイトル経路で担うのは、存在の回復ではなく**表記の異なる語を候補集合に入れること**
（`scoring/index.ts:141-146`）である。両者は別の仕事なので混同しない。

使い捨てにならない理由：手で書いたエントリは最終的な単一資産スキーマを使うので、
後から出典由来の見出し語を同じ資産に足せる。

## 濾過とストップワードの調停

**積極的に濾す。ストップワード方針が常に勝つ。**

- 内容語のカテゴリだけを残す。助詞・助動詞・接続詞・代名詞・文法的助数詞・
  固有名詞（初期は）・1文字表層形は棄却する。
- 混在表記（漢字＋平仮名）と異表記を持つ形を優先する。
- **読みが同じというだけで等価グループを作らない。** 全ての正規化グループは明示的なレビューを要する。
  辞書の lemma / 正規化形フィールドは候補の証拠であって、自動的な権威ではない。

調停規則：

- 認識された表層形が該当するストップワード集合にあるなら、
  語彙トークンもグループキーも**どちらも出さない**。
- 等価グループの一部の要素が抑制され、他が保持される場合、**そのグループを自動取り込みしない**。
  グループ全体をレビューするか破棄する。さもないと正規化が、
  抑制したはずの概念を別名経由で復活させる。

## コミット前に仕様化が必要な未決事項

- **最長一致の意味論**：leftmost-longest、非重複であることの明示。
  句読点・ASCII・より長い未知複合語との相互作用。曖昧なままだと実装が分岐する。
- **バージョン同一性**：索引の世代ごとに単一の不変な語彙表バージョン。ホットスワップ禁止。
- **出自の固定**：上流のリリース／エディションをピン留めし、Apache / UniDic の告知を保持し、
  濾過の変換内容を記載する。core/full は NEologd 由来の出自を監査するまで取り込まない。
- **`standalone` ゲートとの相互作用**：上の「frozen corpus との関係」は語彙表が不変であること
  （vault の編集で変異しない、あるノートの認識が他ノートに波及しない）を論じたものであって、
  トライのヒットと `addKanjiRun` 内の凍結 `standalone` ゲートが実際に干渉しないことを
  追跡確認したものではない。実装時に確かめる。

## 順序について

「辞書を持つべきか」と「辞書が次の一手か」は別の問いだが、**両方 yes である。**

一時、既定経路の欠陥（fixture の25表層形中13が0トークン）を理由に
辞書を後回しにする案を検討したが、これは誤りだった。理由は下記の撤回節を参照。

## 議論の過程で撤回された見解

Claude 側：

- **漢字骨格キー**（平仮名を落として漢字を連結し、2漢字以上に限定すれば安全）。
  `NEGATIVE_CONTRAST_PAIRS` は元々この規則を否定するために作られており、
  5件すべてが2漢字骨格を共有するため誤マージは 0/5 → 5/5 になる。
  データセット前半だけを読んで提案した。
- **「辞書は既定経路では無力」**。辞書をトークンの正規化器としてのみ捉えた誤り。
  `titleTokens.ts` は basename を丸ごと `tokenize()` に渡しており、
  生の文字列が手元にある。語彙表は**認識器**として働けるため、
  正規表現が何も出せない文字列にこそ価値が高い。
- **順序の主張**（既定経路の構造欠陥を先に潰し、辞書は後）。
  上記が誤りだったため土台を失った。辞書は既定経路の修正そのものである。
- **タイトル経路のセグメンタOFFを settled decision として扱ったこと**。
  CLAUDE.md:13 の「do not re-propose」リストは温度フィルタ・incremental df・
  ロックの3つのみで、タイトルのセグメンタ設定は含まれない。
- **「表層形は常に出し続ける」という不変条件の書き方**。
  既存ストップワードが意図的に抑制している語を復活させてしまう。
- **「加算的だから誤マージは構造的に0」**。等価グループの誤りや、
  未知複合語内部の部分語認識で誤マージは生じうる。
- **「6信号の加重和なので1トークンの取りこぼしは軽い」「効果は既定OFFの経路に落ちる」**
  （価値評価で自ら立てた反論）。タイトルトークンは候補集合を広げ、
  本文経路には df≥2 の閾値がある。どちらも加算ではなく可否の問題だった。
- **分類2を「実害ほぼ無し」としたこと。** `2 ≤ df ≤ 40%` の漏れ形はゲートを通過する。
- **分類3に「全ひらがな文字列」を入れたこと。** TinySegmenter の平仮名分岐で部分的に到達可能。

Codex 側（第1ラウンドから修正された点）：

- 最小資産を「小さな異表記変換表」としたこと。
  認識器として使うには見出し語のカバレッジが要り、コミットの大きさが変わる。
- SudachiDict を単に Apache-2.0 として扱えるとした点は、
  第3ラウンドで LEGAL の UniDic / NEologd 出自を指摘して自ら修正した。
